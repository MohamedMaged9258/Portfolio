# SEO

How this site is set up to be found, and the off-site steps that only you can do.

The target query is **"Mohamed Maged"**. Be realistic about it: that name belongs to an
IMDb film director, an Olympic weightlifter with a Wikipedia article, an MMA fighter, a
Cairo University professor, and over a thousand LinkedIn profiles. You are not going to
outrank those for the bare two-word name any time soon, and nothing in this document
pretends otherwise.

What is winnable:

- **"Mohamed Maged" + a qualifier** — AIOps, portfolio, AI engineer, Alamein, Flutter,
  DEPI, Proxmox. These are the queries a recruiter who has your CV actually types.
- **Entity consolidation** — getting Google to treat this site, your GitHub, and your
  LinkedIn as one person. That is what eventually earns a slot on page one for the bare
  name, next to your own LinkedIn profile rather than instead of it.
- **Being the answer in AI search** — ChatGPT, Claude, and Perplexity read raw HTML.
  This site now serves them real content.

---

## What the build already does

Run `npm run build` and `dist/` gets:

| Output | Why |
|---|---|
| Fully rendered HTML per route | Crawlers that don't execute JS (Bing, DuckDuckGo, GPTBot, ClaudeBot, PerplexityBot) see real content, not an empty `<div id="root">` |
| Per-route `<title>`, description, canonical, `og:*`, `twitter:*` | Each page unfurls and ranks as itself instead of as a copy of the homepage |
| `robots.txt` | Points crawlers at the sitemap; explicitly allows AI crawlers |
| `sitemap.xml` | Lists every indexable route with a `lastmod` from the content's own frontmatter |
| JSON-LD (`Person`, `WebSite`, `ProfilePage`, `BreadcrumbList`, per-project nodes) | The machine-readable claim that this site is about a specific person, with `sameAs` linking to your other profiles |
| `404.html` | Unknown URLs return a real 404 instead of 200-with-the-app, which was wasting crawl budget |

All of it is generated by `scripts/prerender.mjs` from `data/profile.json` and the MDX
frontmatter. **The production URL lives in exactly one place — `site` in
`data/profile.json`.** Nothing else hardcodes it.

## Off-site checklist

Do these in order. Step 1 is the one that matters most: as of writing,
`site:mohamedm.dpdns.org` returns **nothing**, because a new domain with no inbound links
never gets crawled in the first place. Everything above is wasted until this is done.

### 1. Google Search Console — the actual unlock

1. Go to [search.google.com/search-console](https://search.google.com/search-console).
2. Add a **Domain** property for `mohamedm.dpdns.org`.
   - Domain properties verify by DNS TXT record. Add it in the Cloudflare dashboard under
     **DNS → Records**. If the DigitalPlat setup makes DNS awkward, use a **URL prefix**
     property for `https://mohamedm.dpdns.org/` instead and verify by HTML tag — paste the
     `<meta name="google-site-verification" ...>` tag into `index.html`, above the
     `<!-- Open Graph -->` comment. It is a plain tag; `prerender.mjs` will not touch it.
3. **Sitemaps → Add a new sitemap →** enter `sitemap.xml` and submit.
4. **URL Inspection →** paste `https://mohamedm.dpdns.org/` → **Request Indexing**.
   Repeat for `/projects` and each project URL. This is the manual nudge that gets a
   brand-new site into the crawl queue instead of waiting weeks to be discovered.

Check back in about a week: **Indexing → Pages** should show the URLs moving from
"Discovered" to "Indexed".

### 2. Bing Webmaster Tools

[bing.com/webmasters](https://www.bing.com/webmasters) → **Import from Google Search
Console** does the whole thing in two clicks. Worth it: Bing feeds DuckDuckGo and
ChatGPT's search, which is a meaningful share of "who is this person" lookups now.

### 3. LinkedIn — your strongest inbound link

LinkedIn ranks extremely well for personal names, and it is the most reliably crawled
page that can point at you.

- **Contact info → Website:** `https://mohamedm.dpdns.org` (label it "Portfolio").
- **About section:** write the URL out in the text as well. The Website field is often
  `nofollow`; body text is not, and it is what a human reads anyway.
- **Headline:** make it match `title` in `data/profile.json` — currently
  *AIOps Engineer*. Consistency across profiles is what merges them into one entity.
- Set a **custom public profile URL** if you haven't (`linkedin.com/in/mohamed-maged05`
  is already fine).

### 4. GitHub — the second strongest

GitHub profiles are crawled aggressively and rank well.

- On [github.com/MohamedMaged9258](https://github.com/MohamedMaged9258), set the
  **Website** field to `https://mohamedm.dpdns.org`.
- Set **Name** to exactly `Mohamed Maged` and **Bio** to your title.
- Create a **profile README**: a repo named `MohamedMaged9258`, containing `README.md`.
  It renders on your profile page. Link the portfolio from it, and link the individual
  project write-ups (`/projects/homelab`, `/projects/churn-prediction`, …).
- In each project repo, set the **About → Website** field to that project's page on this
  site. Free, relevant, and it points crawlers at your deep pages rather than only the
  homepage.

### 5. Keep the name identical everywhere

Search engines merge entities on exact matches. Pick one spelling and one job title and
do not vary them:

- Name: `Mohamed Maged`
- Title: `AIOps Engineer`

That means the site, LinkedIn, GitHub, your CV PDF, and any conference or course profile.
The site side is already consistent — it all flows from `data/profile.json`.

### 6. Replace the Open Graph image

`data/assets/Profile.png` is **848×1264 — a portrait**. The build detects this and
correctly emits `twitter:card=summary` (a small square card) rather than
`summary_large_image`, which would crop a portrait into a mess.

To get the large banner card, add a landscape image:

- **1200×630 px**, PNG or JPG, under ~1 MB.
- Put your name in large type, your title underneath, and keep the important content
  inside the middle ~1000×500 — the edges get cropped at some aspect ratios.
- Save it over `data/assets/Profile.png`, or add it as a new file and update
  `DEFAULT_IMAGE` in both `scripts/prerender.mjs` and `src/lib/site.ts`.

`prerender.mjs` reads the dimensions out of the PNG header at build time, so
`og:image:width` / `:height` and the card type update themselves. Nothing to remember.

### 7. Optional accelerators

Only worth doing once the above is done:

- Write up a project on **dev.to** or **Hashnode** and link back here. The home lab post
  is the most naturally interesting one to a technical audience.
- Answer questions on **Stack Overflow** with the site in your profile.
- Ask whether **Alamein International University** lists student or project pages you
  could appear on. A `.edu`-equivalent inbound link is worth many ordinary ones.
- If you present anywhere or complete a notable course, get the certificate page up —
  see the content gap below.

## The content gap

Two things limit how much there is to rank, and neither is a technical problem:

- **`data/certificates/` is empty.** The entire collection — routes, cards, detail pages,
  `EducationalOccupationalCredential` structured data — is built and shipping nothing.
  The nav tab is hidden and `/certificates` says "Nothing here yet". Adding real
  certificates is the highest return-per-effort work available: each one is an indexable
  page carrying issuer names people actually search for. See `docs/CONTENT.md`.
- **Four projects, one of them not featured.** Depth beats breadth — a thorough
  `case-study` write-up on an existing project is worth more than a new stub.

## Verifying it worked

After deploying:

```sh
# Real 404, not 200-with-the-app. Only true once deployed — `vite preview`
# has its own SPA fallback and will still answer 200 here.
curl -I https://mohamedm.dpdns.org/some-junk-url

# Plain text, not HTML
curl https://mohamedm.dpdns.org/robots.txt
```

- **View source** on the homepage (`Ctrl+U` — not DevTools' Elements panel, which shows
  the hydrated DOM). Your name and bio must be in the raw HTML.
- [Rich Results Test](https://search.google.com/test/rich-results) on the homepage →
  should detect `Person` and `ProfilePage`, with both profile URLs under `sameAs`.
- [Schema Markup Validator](https://validator.schema.org/) for the full graph.
- [OpenGraph.xyz](https://www.opengraph.xyz/) to preview how a shared link unfurls.
- `site:mohamedm.dpdns.org` on Google, about a week after requesting indexing.

Then, over the following weeks, watch **Search Console → Performance** for which queries
actually bring people in. If "mohamed maged" starts showing impressions at position 30,
that is the signal the entity work is landing.

## Appendix: moving to a real domain

Staying on `mohamedm.dpdns.org` is the main ceiling on the bare-name query. It is on the
Public Suffix List, so it is treated as its own site rather than sharing signals with
other DigitalPlat users — but it has no domain age, no authority of its own, and a free
subdomain is a weak signal for a query that is a person's name. An exact-match domain
(`mohamedmaged.dev`, `.com`, `.me` — roughly $12–15/year) is the single highest-leverage
change available.

When you buy one:

1. Add the domain to Cloudflare and point it at the same Worker
   (**Workers & Pages → portfolio → Settings → Domains & Routes**).
2. Change **one line** — `site` in `data/profile.json` — then `npm run build`. Every
   canonical, `og:url`, sitemap entry, and JSON-LD `@id` follows automatically.
3. Keep `mohamedm.dpdns.org` alive and **301-redirect** it to the new domain. Do not just
   turn it off; the redirect is what passes along whatever authority it has accumulated.
   Add a Cloudflare **Redirect Rule**: match hostname `mohamedm.dpdns.org`, dynamic
   redirect to `concat("https://mohamedmaged.dev", http.request.uri.path)`, status 301,
   preserve query string.
4. Add the new domain as a Search Console property, verify it, and submit the sitemap.
5. In the **old** property, use **Settings → Change of address** to tell Google the site
   moved. This is what migrates the ranking signals rather than starting from zero.
6. Update the URL on LinkedIn, GitHub, and anywhere else from the checklist above.

Expect a few weeks of turbulence in rankings after a move. Do it sooner rather than later
— the migration cost grows with the authority you would be moving.
